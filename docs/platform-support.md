# Platform feasibility and provider verification

Historical Windows evidence date: 2026-10-19. Windows host: Windows 11 build 26200, x64, WebView2 Evergreen 155.0.4283.62, current monitor scale 1.0. Tauri 2.12.4 / tauri-build 2.7.3 / tauri-runtime-wry 2.12.2 / Wry 0.57.0; exact resolved versions are in Cargo.lock. Node 24.15 and Rust 1.98 were used. No memory or performance advantage has been measured.

Current Linux findings and graphics-shutdown limitations are recorded in the [Linux section](#linux-implementation-findings-2026-10-19) and [verification log](verification.md#linux-continuation--2026-10-19).

## Native architecture findings

The phase-1 test was performed before the UI port. It created a trusted local shell and two independently controlled native child webviews in one window, with a fixture sending `X-Frame-Options: DENY`. Both used the same origin but separate storage directories. LocalStorage/cookies, popup profile inheritance, lifecycle, restart persistence, targeted clear and command rejection were verified against WebView2. The expanded test additionally exercises the retained UI and Rust OIDC/API services. See [initial evidence](evidence/phase1-windows.json) and [final native evidence](evidence/native-windows.json).

The [Tauri WebviewBuilder API](https://docs.rs/tauri/2.12.4/tauri/webview/struct.WebviewBuilder.html) and downloaded sources were inspected. `Window::add_child` needs `unstable`, explicitly enabled here. Creation happens from async commands, avoiding the documented Windows synchronous-command creation deadlock. `window_features` carries the opener environment/configuration/related view into a popup. Rust owns view labels, generations, profile paths and lifecycle; the shell submits validated logical rectangles. Native measurements confirmed conversion at the local monitor's scale 1.0. Mixed-DPI monitors remain unverified.

On Windows, the trusted shell is a transparent WebView2 surface. `drawer_layer.rs` raises its Wry-owned child HWND above route views while a drawer is open and lowers it on close. The existing React drawer/backdrop then composites over live websites. No additional privileged view or capability is introduced. Native on-screen pixel sampling verified two different underlying page colours through the 20% backdrop, with unchanged view generation; resize, click-outside close, Escape and focus restoration passed ([evidence](evidence/windows-live-drawer.json)). This uses the pinned [transparent WebviewBuilder option](https://docs.rs/tauri/2.12.4/tauri/webview/struct.WebviewBuilder.html#method.transparent) and Windows sibling HWND ordering, not CSS z-index across webviews. Linux/macOS retain the prior hide/show path until engine-specific native stacking/compositing is implemented and verified. Switching tabs hides existing views; hibernation destroys them. The app creates all non-hibernated routes, so previously visited and background routes remain alive. Engines may still throttle background execution.

Windows requirements follow [Microsoft's WebView2 supported platforms](https://learn.microsoft.com/en-us/microsoft-edge/webview2/) and [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/). This project does not promise compatibility with every historical Tauri-supported OS. WebView2's asynchronous `ClearBrowsingDataAll` is called through `ICoreWebView2Profile2`; unsupported runtimes return an error. Use Evergreen rather than relying on an obsolete minimum runtime.

Wry's named WebKit store support requires macOS 14/iOS 17; see the pinned [data_store_identifier API](https://docs.rs/tauri/2.12.4/tauri/webview/struct.WebviewBuilder.html#method.data_store_identifier). Linux clears a whole WebContext, which is why separate per-route directories are mandatory. Tauri's [clear_all_browsing_data contract](https://docs.rs/tauri/2.12.4/tauri/webview/struct.Webview.html#method.clear_all_browsing_data) explicitly says deletion is asynchronous. Epoch rotation ensures a cleared route cannot reopen the old store while physical cleanup is pending.

The portable permission callback only supplies a webview and permission kind, not requesting/embedding origins. Windows has a dedicated COM adapter; Linux/macOS deny rather than grant media to arbitrary child frames. Native origin-aware adapters are the concrete next implementation step. These are explicit gaps, not a claim that those engines can never support the feature.

## DRM

Castlabs Electron is not included. No bundled Chromium, Node sidecar or header/security bypass is used. Microsoft's [Widevine feature request](https://github.com/MicrosoftEdge/WebView2Feedback/issues/4828) remains open at inspection; that alone does not establish every provider's playback outcome. `scripts/native-smoke.mjs` probes EME key-system negotiation on the installed WebView2 and records results in the evidence JSON. On this host, both `com.widevine.alpha` and `com.microsoft.playready.recommendation` accepted the tested AAC/H.264 configuration. Successful negotiation is not a license exchange or playback test. Spotify must be tested with a consenting user's existing account after the migration; no credentials were requested or fabricated.

If required playback cannot work on the target engine, the smallest alternatives are opening that service in the system browser or retaining the Electron app for that service. Neither fallback is silently enabled. A product decision is needed only after the required provider test establishes the actual failure.

## Manual native/provider checklist

Every unchecked case is **implemented-unverified** unless the engine matrix marks it unsupported. Use ordinary test accounts you control; never put credentials in repository files or test reports.

- [x] Windows mock OIDC/API: PKCE, native credential store, route CRUD, offline cache/recovery, invalid-session rejection, cold callback and replay rejection. This does **not** verify production Authentik login.
- [ ] Move between monitors at 100%, 125%, 150% and 200%; resize while opening/closing all drawers. Check focus and background route persistence.
- [x] Linux Hyprland Wayland and Xwayland fixtures: isolated stores/restart, popup opener, native geometry, mock OIDC/API and explicit missing-keyring errors. Pure Xorg and mixed-monitor behavior remain unverified.

- [ ] Production Omnia Authentik: sign in, cancel, restart, refresh rotation, logout, temporary outage, revoked refresh token, two Omnia users and route ownership.
- [ ] Gmail/Google: traces identified missing `accounts.youtube.com`, followed by `accounts.google.pl`. Regional account support uses exact HTTPS hosts from a pinned [official Google domain list](https://www.google.com/supported_domains), scoped to Google-enabled routes. Unit checks pass for the entire account list; the extended Polish/UK/German native fixture passed with no external handoff and with duplicate-profile isolation ([evidence](evidence/windows-gmail-regional-after.json)). Actual login including MFA, duplicate-account isolation, unread title/DOM, mail links and Meet permissions remain unverified.

## Linux implementation findings (2026-10-19)

The Linux continuation starts at target commit `393b7123f9239628cb22da630bc6793d7f9e7250`; source Omnia main is still `4c76ff5bd8d574448ec2c99d890373a64059c287`. Host: Omarchy 4.0.4 x86_64, GTK 3.24.52, WebKitGTK 2.52.6, Hyprland Wayland with one 1920×1080 scale-1 display. Native results will be recorded independently in `evidence/native-linux.json`.

The exact `tauri-runtime-wry 2.12.2` `WebviewWrapper::drop` implementation intentionally retains Linux WebContexts for the entire app lifetime (upstream issue 14626), including after the last view closes. Linux profile cleanup therefore records retired directories and removes them on the next startup before creating views. Epoch rotation immediately prevents reopening the retired session. Hibernation destroys the view, but does not promise termination of the associated network process or a particular memory saving.

Installed WebKitGTK 2.52.6 headers and `webkit2gtk 2.0.2` bindings were inspected alongside the official [UserMediaPermissionRequest](https://webkitgtk.org/reference/webkit2gtk/stable/class.UserMediaPermissionRequest.html) and [NotificationPermissionRequest](https://webkitgtk.org/reference/webkit2gtk/stable/class.NotificationPermissionRequest.html) APIs. They expose device-kind flags and allow/deny, without a requesting SecurityOrigin/frame. A top-level URI check alone cannot authorize cross-origin frames. Camera/microphone/website notifications remain denied; adding a safe adapter needs an upstream origin-bearing request API or a separately reviewed WebKit web-process extension with trustworthy frame identity. No permission grant or OS notification-delivery claim is made.

The pinned autostart plugin's `auto-launch 0.6.0` Linux code hardcodes `~/.config/autostart` and ignores `XDG_CONFIG_HOME`. Omnia now has a focused Linux XDG adapter with atomic desktop-entry writes and Exec escaping; Windows/macOS retain their plugin path. Testing uses a private XDG directory and never enables the user's login startup. A compositor must actually implement XDG autostart for login launch to work. Minimize remains a window-manager request, not a guaranteed Wayland behavior.

The pinned Tao Linux badge adapter requires libunity and a Unity-compatible launcher. Hyprland's bar is not evidence of that protocol's visual rendering; window title and sidebar counts remain useful independently. Zero now clears the launcher badge with `None`.

Linux smoke instrumentation uses [WebKit's async JavaScript API](https://webkitgtk.org/reference/webkit2gtk/stable/method.WebView.call_async_javascript_function.html) (WebKitGTK ≥2.40) on the actual native views and reads their GTK allocations/context/data-manager identities. It is compiled out in release, requires `OMNIA_SMOKE=1`, a private 0700 directory and isolated XDG data/config/cache paths, and exposes a 0600 Unix socket only. It adds no Tauri capability or HTTP server. WebKitWebDriver is not installed here; simply launching Playwright WebKit would not verify Tauri's runtime. Native DOM actions through this harness are not hardware pointer-gesture evidence.

A native failure exposed that `tauri-runtime-wry 2.12.2` builds Linux child webviews in the window's vertical GtkBox; Wry's `set_bounds` only acts on X11 child windows or GtkFixed parents. This stacked the shell and routes vertically and ignored requested bounds. `geometry_linux.rs` reparents the same native WebKit views into a GtkLayout and applies logical child coordinates/size requests. GtkLayout clips overflow without making the entire window's minimum size equal to the child extent. GTK handles buffer scaling; the adapter must not multiply logical coordinates a second time. Native smoke measures GTK allocations, identities and visibility instead of trusting the Wry getter's default position. The saved pre-fix failure is [linux-geometry-before.json](evidence/linux-geometry-before.json).

**Linux graphics shutdown gap:** a later run on WebKitGTK 2.52.6 completed all scenarios but a WebKitWebProcess aborted in libc allocator cleanup during exit. See [crash evidence](evidence/linux-xwayland-shutdown-failure.json). The main app exited, but this is not a clean native shutdown. The exact heap-corruption source is unresolved; no sandbox, web-security or GPU flags were disabled. Retest on a supported distro's newer WebKitGTK and minimize the reproducer before reporting upstream. Earlier clean Xwayland runs do not establish that this intermittent issue is fixed.


A later strict Wayland run also aborted a WebKitWebProcess during exit. Its core includes NVIDIA EGL 580.178.04 cleanup frames; this hybrid Intel UHD 620/NVIDIA MX150 host inherits `__GLX_VENDOR_LIBRARY_NAME=nvidia`. A comparison with `WEBKIT_DISABLE_DMABUF_RENDERER=1` passes all 22 checks and five clean exits: [explicit-renderer evidence](evidence/native-linux-dmabuf-disabled.json). This is the documented [Tauri Linux graphics workaround](https://v2.tauri.app/develop/debug/linux-graphics/), at the cost of the faster rendering path. Default-renderer failures remain recorded; the application does not silently set this option or disable sandbox/web security. Real media performance/provider compatibility under the alternative path remains unverified.

### AppImage audio crash correction — 2026-10-22

The installed/downloaded 0.11.0 AppImage had no GStreamer plugin directory or media launch hook. Its bundled GStreamer 1.24.2 could not use the Arch host's 1.28.6 plugins. Repeated runtime logs report missing `appsink`, `appsrc`, and `autoaudiosink`; the October 21 core's abort return address (`libwebkit2gtk-4.1.so.0 + 0x3375cc0`) follows an assertion whose embedded source/function strings identify `MediaPlayerPrivateGStreamer.cpp:1601`, `createAudioSink()`. Full debug symbols are absent; the extracted core was deleted after inspection. No OOM kill was recorded. This is distinct from the graphics shutdown issue above.

`bundle.linux.appimage.bundleMediaFramework` now includes the media stack, using Tauri's [documented bundling option](https://v2.tauri.app/distribute/appimage/#multimedia-support-via-gstreamer). CI installs base/good/libav plugins before bundling, then checks the finished AppImage. `scripts/check-appimage-media.py` verifies engine libraries and required plugins resolve inside the package and exercises silent HTML audio plus three Web Audio contexts using ephemeral storage. Its controlled autoplay policy is test-only; application permissions/behavior are unchanged. It adds no runtime sidecar or capability.

**implemented-and-tested** for packaged audio initialization: the old package reproduces WebKit process termination on silent HTML audio; the rebuilt package completes playback and advances/closes three Web Audio contexts, with the normal renderer and separately with the explicit DMABUF workaround. [Evidence and artifact hashes](evidence/linux-telegram-media.json). The real Tauri fixture also passes 22 checks/five clean exits with the explicit workaround ([native evidence](evidence/linux-telegram-media-native.json)). These tests do not establish Telegram account stability, audible output, calls, provider video codecs, DRM, or resolution of the graphics shutdown gap. Ubuntu CI and Windows/macOS were not run locally. Rebuilt AppImage size is about 151 MiB; previous size measurements predate required media bundling.
