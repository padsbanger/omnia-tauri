# Source parity and evidence

Reference: `padsbanger/omnia`, default branch `main`, commit `4c76ff5bd8d574448ec2c99d890373a64059c287` (v0.11.0), fetched 2026-10-19. It matches the commit supplied in the task. Source paths below are relative to that read-only sibling checkout. This is a runtime migration, with reused MIT React/CSS/assets/domain tests, not an API recreation of the hosted websites.

Status meanings: **implemented-and-tested** means the stated scope has actual local evidence; **implemented-unverified** means code exists but the stated runtime/provider case was not exercised; **unsupported** means the UI or documentation explicitly discloses the missing capability; **blocked** means a required external prerequisite prevents verification. Windows evidence does not imply Linux/macOS parity.

Evidence references: `npm run test:coverage` exercises the TypeScript/domain/UI suite; `npm run native:test` exercises native logic; `npm run smoke` builds and drives actual Windows WebView2 views with deterministic HTTP/OIDC fixtures. [Native report](evidence/native-windows.json), [phase-1 report](evidence/phase1-windows.json), [verification record](verification.md), and [platform/provider checklist](platform-support.md) distinguish these scopes. Browser fixture mocks replace only external servers, not the native browser runtime.

## Scope limits requiring follow-up

Latest Gmail trace: YouTube's account step stayed internal, but the subsequent accounts.google.pl step was external. Shared pinned Google account hosts and exact HTTPS regional matching are implemented and unit-tested. The full native fixture now passes through YouTube and Polish/UK/German account hosts without an external handoff, retaining profile isolation (windows-gmail-regional-after.json). Actual account retry is pending; synthetic native success does not establish provider login success.

The Windows native architecture is feasible for isolated website workspaces. This does not establish full product/provider parity. Next gates are the account/hardware checklist, mixed-DPI testing and running the supplied Linux/macOS CI plus native smoke cases. Media permission adapters on WebKit and macOS named-store removal need implementation/verification. If an essential service fails DRM or login on the system engine, retain that service in Electron or explicitly open it in the system browser after the product decision; no fallback is silently applied.
