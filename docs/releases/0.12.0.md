# Omnia Tauri 0.12.0

Vaultwarden autofill is available from the workspace. Configure your HTTPS vault URL, unlock, and lock the vault in **Settings → Vaultwarden**. The sidebar vault icon appears while unlocked and becomes active when the selected website has a matching personal login. Choose an entry to fill its username and password; Omnia leaves form submission to you.

The vault URL is stored locally for the signed-in Omnia account and has no bundled default. Rust owns the vault session and encrypted data. Filling is limited to exact HTTPS origins and a live native route view. Shared organization entries, SSO, non-authenticator 2FA, service popups, frames and passkeys remain unsupported.

Windows verification passed 135 frontend tests with coverage and CRAP8, 34 Rust tests, lint, typecheck, fmt, Clippy, frontend/native builds and a deterministic WebView2 smoke run covering Settings, sidebar availability, route navigation, filling and command denial. The smoke run uses synthetic vault data; real account/provider login and Linux/macOS runtime behavior remain unverified. See [Vaultwarden support](../vaultwarden.md) and [Windows evidence](../evidence/windows-vaultwarden-settings.json).

Installers attach after GitHub Actions verification and platform builds succeed.
