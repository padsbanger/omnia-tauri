# Omnia Tauri 0.11.2

Patch release prepared on 2026-10-22, following 0.11.1.

## Fixes

- Package the GStreamer media framework and required plugins in the Linux AppImage. This addresses the observed Telegram/WebKit subprocess abort when audio playback could not create its GStreamer sink.
- Make the Linux native smoke driver distinguish parent-process exit from delayed inherited output-stream closure, retain late crash diagnostics, and apply bounded cleanup deadlines. This addresses the intermittent Ubuntu Actions shutdown failure that prevented the 0.11.1 release artifacts from being attached.
- Keep the dedicated Node subprocess regression separate from Vitest frontend discovery, fixing the subsequent frontend coverage job failure.

## Release packaging

- Linux CI installs the media development/runtime dependencies required by the bundled AppImage and verifies the finished AppImage with deterministic HTML Audio and Web Audio probes.
- The release workflow still attaches DEB, RPM, AppImage, MSI, NSIS EXE and DMG installers only after frontend checks and all three native platform jobs succeed.

Windows x64 EXE, MSI and NSIS outputs were built locally in an isolated Cargo target directory while the installed 0.11.1 application remained running. Their application versions were checked as 0.11.2 and [SHA-256 checksums](0.11.2-SHA256SUMS.txt) are recorded. These unsigned local outputs were not installed or uploaded; GitHub Actions rebuilds the tagged source for release assets.

## Upgrade notes

The application identity, backend configuration, credential namespace and website profile paths are unchanged. This update does not deliberately clear existing sessions. Linux AppImage users should replace the previous package; the media-enabled AppImage is expected to be larger.

## Verification and known limitations

The Linux media packaging change passed a finished-AppImage plugin provenance check plus deterministic HTML Audio and Web Audio playback on the documented Arch/Hyprland host. The full Linux native fixture passed 22 checks and five clean exits with `WEBKIT_DISABLE_DMABUF_RENDERER=1`. This does not establish real Telegram account playback, audible hardware output, calls, provider video codecs or DRM support.

The default-renderer NVIDIA/WebKit shutdown issue remains distinct and unresolved. Windows/macOS packages and Ubuntu behavior require the release CI run. See [verification](../verification.md), [platform support](../platform-support.md), and the retained [Linux media evidence](../evidence/linux-telegram-media.json).
