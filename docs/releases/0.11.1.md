# Omnia Tauri 0.11.1

Patch release prepared on 2026-10-21, following 0.11.0.

## Fixes

- Remember the window's normal size and maximized state after closing and reopening Omnia. Closing while minimized preserves the previous maximized state. The embedded interface fills the restored window correctly.
- Clear Gmail's unread badge when the last unread message is read. Title and DOM hints now share delivery history, preventing an earlier zero count or failed stale hint from leaving the badge stuck.

## Release packaging

- Actions downloads include the application version in their names.
- The release workflow builds the tagged commit, checks version consistency and attaches installers to the existing release after frontend checks and all three platform builds succeed.

Windows x64 EXE, MSI and NSIS installers were built locally with `npm.cmd run native:build`. The application and MSI product versions were checked as 0.11.1. [SHA-256 checksums](0.11.1-SHA256SUMS.txt) and [artifact sizes/paths](../evidence/windows-artifacts.json) are recorded. Installers are unsigned and were not installed; Linux/macOS 0.11.1 bundles await CI.

## Upgrade notes

The application identity, backend configuration, credential namespace and website profile paths are unchanged. This update does not deliberately clear existing sessions. Window preferences are saved on normal exit; forced termination may lose recent changes. Maximize once and close normally to establish the new preference.

## Verification and known limitations

On 0.11.1, lint, TypeScript checking, 117 frontend tests with coverage/CRAP threshold 8, 24 Rust tests, formatting/clippy, and the three focused Windows native restart checks passed. [Version-specific native evidence](../evidence/windows-0.11.1-restart.json).

Windows restart behavior has native WebView2 fixture coverage; Gmail badge clearing has deterministic native HTTPS fixture coverage. Real Gmail account behavior and taskbar overlay visuals have not been verified by the agent. Linux/macOS window restoration and mixed-monitor DPI remain unverified.

The latest full Windows smoke suite stopped at an existing on-screen pixel assertion. Its passing individual checks do not establish a full-suite pass. Linux has a documented intermittent WebKit/NVIDIA shutdown failure with the default renderer; successful runs with the explicit DMABUF workaround do not establish a general fix. See [verification](../verification.md) and [platform support](../platform-support.md).
